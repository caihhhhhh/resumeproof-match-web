# ResumeProof 使用逻辑与设计检查

日期：2026-10-22。检查方式：双独立评估，A 为 design_review_a，B 为 design_evidence_b。A 完成判断后，主审才接收 B 的检测器结果。

## 结论

适合做一次有范围的体验重整，保留现有三段流程与证据机制。优先修复重试时的草稿保护、结果的下一步指引和编辑导出的确定性，再调整首页构图。此次只做检查和报告，没有修改产品源码或上线。

首页是帮助访客理解价值的展示面；匹配、编辑、导出是完成任务的操作面。design-taste-frontend 用于首页，impeccable 用于全流程与技术检查。建议首页设计参数：DESIGN_VARIANCE 6、MOTION_INTENSITY 4、VISUAL_DENSITY 3；操作区采用熟悉的控件、适中的信息密度与短状态过渡。现有 React、CSS、GSAP 可以支撑这些调整，无需换框架。

- 未上传个人资料、未调用生产 AI 分析、未提交反馈。临时浏览器页均已关闭；未启动本地服务器或改变视口。

## 设计判断与参考转化

当前产品有自己的证据逻辑，但外观仍主要依赖白底、蓝按钮、圆角面板。更有辨识度的视觉材料已经存在于产品内部：岗位原句、经历证据、修订痕迹与最终简历。

Studio NA.EO 首屏通过黑白、分栏文字、强烈字号对比与明确的对齐建立秩序。可借鉴文字本身承担构图、信息有清楚的列关系；它的超大装饰性汉字和密集导航不适合直接迁移到操作区。官网：https://www.studionaeo.com/

Tian Design 当前首页以很轻的导航和大幅作品图为主体。可借鉴成果优先，让用户先看到有价值的产物。ResumeProof 应展示可核验的简历改动与实际成稿；不应把工具首页变成需要猜操作方式的作品画廊。官网：https://www.tian-design.com/ ，项目说明：https://www.tian-design.com/works

建议视觉方向：保留现有浅底与蓝色动作，用统一无衬线字体、明确的对齐轴和克制的修订标记建立身份。桌面首屏让价值说明与可读的真实交互示例同时出现；手机先给清楚的入口，再展示一个完整例子。现有纸张翻转与滚动放大可以保留，但不要让证明价值的内容只在长距离滚动后才出现。

## 五项优先改进

### 1. P1：让投递结论直接引导用户完成下一步

现状：示例显示“确认后再投递”，但硬条件的原句与解释藏在默认关闭的“评分依据与岗位硬性要求”。顶部与底部进入审核稿的文案也不同；用户可能不知道当前审核的是原文还是已合并稿。

调整：结论旁直接列出未确认/不满足项，并提供“查看岗位原句”“补充真实证据”的路径。保留评分解释折叠。审核入口统一显示“已采用 N 条”，0 条时说明继续审核原文。加一条轻量的位置提示“材料 / 判断与修改 / 审核导出”，不增加强制页面。把效果反馈移到用户完成实际修改或导出后。

位置：app/match/new/page.tsx:1056、1059、1060、1068、1109；app/components/optimization-review.tsx。

适用工具：impeccable clarify / onboard。

### 2. P1：保护已完成的工作，处理时机说在动作旁

源码确认：runAiAnalysis 在请求成功前就清空 reviewDraft、reviewBlocks、采用决定和确认状态；失败分支没有恢复。上传替换文件也会提前清空已有材料。现有 sessionStorage 保存不能解决这个问题，因为清空状态也会被保存。

调整：请求期间保留上一份有效报告与编辑稿，新结果通过校验后再切换。失败时可以回到旧稿；提供取消等待和针对失败环节的重试。已有后端核心分析与建议请求并行，不应把“改为并行”重复列成新功能。后续用真实耗时数据决定是否加提取缓存、相同输入复用或阶段结果展示。

另一个处理时机问题：图片或扫描文件在选中后可能立即发往视觉识别服务，而最具体的数据处理说明在页面底部。应把识别方式和发送时机就近说明；不必新增一页同意流程。

位置：app/match/new/page.tsx:471、474、515、898、903、920、935；app/api/match/analyze/route.ts:380。

适用工具：impeccable harden / clarify。

### 3. P2：编辑器聚焦当前经历，最终预览以实际产物为准

现状：审核页同时承载模板、事实检查、分区编辑、预览和下载。模板已共用排版参数，但浏览器预览使用 Arial/系统中文字体，PDF 使用 Noto Sans SC/Helvetica。网页以连续纸面估算页数，不是实际 PDF 分页；共享字号和边距不能保证相同换行。

调整：保留公司、职位、时间及每段成果的现有结构，把当前经历展开，其余模块收起并提供分区定位。默认经典单栏，模板作为排版设置。把需要确认的事实变化放在对应经历附近，顶部只总结待处理数。提供大图预览或按需生成实际 PDF 的最终预览，统一预览与导出字体、字重及分页依据；中文字体可本地托管，减少首次下载对外部 CDN 的依赖。手机的编辑与预览切换应保留当前经历与滚动位置。

位置：app/match/new/page.tsx:1084、1090、1106、1112；app/components/resume-document.tsx；app/lib/resume-layout.ts:20；app/lib/resume-pdf.tsx:16、67。

适用工具：impeccable layout / adapt。

### 4. P1/P2：统一可读性、语言恢复与键盘操作

现状：结果页的重要解释仍有 8-11px 的字号；双语恢复逻辑延迟读取已保存语言，却立即写入默认 zh，存在英文偏好被覆盖的问题。高级原文编辑器没有程序化名称，隐藏文件输入也没有上传区域的可见键盘焦点。模式按钮仅用颜色标明选择；模板 radio 缺预期键盘行为。

调整：关键正文 15-16px、辅助说明 13-14px；中文页面统一显示“必须项/重要项”。读取语言完成后再写偏好，并处理存储不可用。补原文编辑器标签、上传区域焦点、控件选中状态和模板方向键操作；结果切换后移动焦点到标题。次级按钮目标统一为舒适的触控尺寸，显式平滑滚动遵守减少动态效果设置。

位置：app/globals.css:771-788、708、717、1405、1431；app/components/language-context.tsx:18-29；app/components/resume-structured-editor.tsx:202；app/match/new/page.tsx:1005、1085。

字号较小和 28-42px 控件需要改善，但不能把每个小于 44px 的控件都声称为 WCAG AA 违规。屏幕阅读器与实际触控仍须后续实测。

适用工具：impeccable typeset / harden / adapt。

### 5. P2：首页把产品价值放到第一眼，动效展示修改关系

现状：当前桌面首屏以居中口号和按钮为主，演示正文只在底部露出一部分。示例把“通过……使注册成本下降”改成“基于……推动注册成本下降”，没有充分展示可核验的结构改善。

调整：借鉴 NAEO 的文字秩序和 Tian 的成果优先。首屏让岗位要求、证据原句与改后表达可同时读到；用一组事实不增加但层级显著更清楚的改写，突出实际改变。再展示一个“现有表达已足够，无需修改”的例子。示例报告持续标明演示状态。动效围绕同一句话的原文定位、修改展开、采用与撤销，操作区过渡约 150-250ms；保留已实现的减少动态效果和清理逻辑。

位置：app/components/home-experience.tsx:74、84、87；app/components/home-experience.css:36、39；app/lib/demo-materials.ts:85-101。

适用工具：design-taste-frontend + impeccable onboard / layout / animate。

## 应保留的基础

1. 证据原句、真实差距和硬门槛机制，是可信度的核心。
2. 采用、修改、保留原文及撤销，已经给用户控制权。
3. 公司/职位/时间分字段编辑、编辑历史和多格式导出已经存在。

## 认知负担与用户视角

认知负担评估为 3/8 项不理想：关键门槛层级偏低、审核页同时引入太多决定、模块库展开后出现 8 个同级选项。

- 初次使用者：需要明确“确认什么”和“现在进入的是什么稿”。
- 手机用户：长简历编辑和预览往返、动作按钮位置值得实测；本次没有完成手机验证。
- 键盘/读屏用户：上传焦点、未命名编辑框、重复上移/删除按钮和页面转换焦点需要完善。

体验高点是能看到依据且没有编造事实；低点是拿到“待确认”的结论却不知道如何解决。结束时应清楚显示采用了哪些改变、哪些仍待补充，以及文件生成是否成功。

## 检测器结果

单次扫描有 7 条命中：side-tab 4、overused-font 2、codex-grid-background 1。逐条核对后，没有确认的范围内装饰问题：一项属于后台，三项为事实/审核警示，字体项属于打印文档，网格项属于当前页面没有使用的旧选择器。没有为了检测器分数建议移除必要状态提示。

精确位置与排除原因见 assessment-b.detector.json 和 assessment-b.notes.md。无浏览器注入覆盖层；只读接口不支持该操作，使用源码、当前页面截图和 DOM 作为替代证据。

## 建议落地顺序与验收

1. 草稿保护、语言恢复、上传焦点和标签；再核对失败后内容是否完整。
2. 投递结论的待确认项、统一审核入口、减少结果页往返。
3. 聚焦编辑、字体与实际 PDF 预览、窄屏操作。
4. 首页构图与真实示例，最后一次集中视觉 polish。

验收以任务为准：失败重试不丢稿；0 条/部分/全部采用都能清楚进入审核；英文刷新能保持；键盘可以上传和切换模板；最终文件内容对应审核稿；手机无横向溢出并能继续当前编辑。真实 AI 与文件导出速度须单独测量，不能把浏览器检查工具的超时当成产品耗时。

## 后续方向选择

视觉可选：保留现有蓝白基础，强化文字网格与修订痕迹（推荐）；或整体转成更强烈的黑白编辑式语言。

执行可选：先完成操作与导出，再统一首页（推荐）；或先做首页视觉验证，再进入操作区。
